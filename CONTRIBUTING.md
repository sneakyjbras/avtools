## 🐛 How to Contribute

### 1. Reporting Bugs
If you find a bug, please create an issue in the repository. When logging a bug, please include:
*   A clear and descriptive title.
*   The version of `avtools` you are using.
*   Your operating system and environment details.
*   Steps to reproduce the behavior.
*   Expected behavior vs. actual behavior.

### 2. Suggesting Enhancements
We welcome feature requests! When suggesting a feature, please include:
*   A clear description of the proposed feature.
*   The problem it solves or the use case it supports.
*   Any potential alternatives you have considered.

### 3. Submitting Pull Requests
We gladly accept pull requests. To make the review process smooth, please follow these steps:

1.  **Fork/Clone the repository** and create your branch from `main` (or `master`).
    ```bash
    git checkout -b feature/my-awesome-feature
    ```
2.  **Make your changes**, keeping your commits small and focused.
3.  **Test your changes** to ensure they do not break existing functionality. *(Add any specific testing commands for avtools here if applicable).*
4.  **Format your code** according to the project's style guidelines.
5.  **Commit your changes** using clear and descriptive commit messages.
    ```bash
    git commit -m "feat: add support for new audio codec"
    ```
6.  **Push to your branch** and open a Pull Request.

---

## 📝 Commit Message Guidelines

We prefer structured commit messages to make the project history easier to read. Please use the following prefixes:
*   `feat:` A new feature
*   `fix:` A bug fix
*   `docs:` Documentation only changes
*   `style:` Changes that do not affect the meaning of the code (white-space, formatting, etc.)
*   `refactor:` A code change that neither fixes a bug nor adds a feature
*   `test:` Adding missing tests or correcting existing tests
*   `chore:` Changes to the build process or auxiliary tools
